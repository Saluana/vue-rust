## Why
Everything the compiled templates call (`createElementVNode`, `openBlock`, `toDisplayString`, `renderList`, …) and everything the renderer consumes (VNodes with shape/patch flags, dynamic children) starts here. Observable behaviour must equal Vue 3.5.43 (production build): flag values are part of the compiler contract (the official compiler emits numeric patch flags).

## Implement
1. `shapes.rs`: `ShapeFlags`, `PatchFlags`, `SlotFlags` with Vue's exact numeric values (`TEXT=1 CLASS=2 STYLE=4 PROPS=8 FULL_PROPS=16 NEED_HYDRATION=32 STABLE_FRAGMENT=64 KEYED_FRAGMENT=128 UNKEYED_FRAGMENT=256 NEED_PATCH=512 DYNAMIC_SLOTS=1024 DEV_ROOT_FRAGMENT=2048 CACHED=-1 BAIL=-2`; shape flags `ELEMENT=1 FUNCTIONAL_COMPONENT=2 STATEFUL_COMPONENT=4 TEXT_CHILDREN=8 ARRAY_CHILDREN=16 SLOTS_CHILDREN=32 TELEPORT=64 SUSPENSE=128 COMPONENT_SHOULD_KEEP_ALIVE=256 COMPONENT_KEPT_ALIVE=512 COMPONENT=6`) plus helpers; verify them against the real package with a Node check in tests.
2. `vnode.rs`: the VNode representation. VNodes are heap objects (`ObjectKind::Native` with a `Rc<VNode>` payload using interior mutability for fields the renderer mutates: `el`, `anchor`, `component`, `suspense`, `target`, `targetAnchor`, `ctx`, `ssContent/ssFallback`, `dynamicChildren`, `patchFlag`, `shapeFlag`, `children`, `props`, `key`, `ref`, `dirs`, `transition`, `memo`, `staticCount`, `appContext`, `scopeId`, `slotScopeIds`, `el` host-node handle type `vn_dom::NodeId`-compatible but defined as an opaque `HostNode(u64)` in `host.rs`'s future trait — use `u64` for now) so identity (`===`) works and the collector sees children/props. Implement: `Fragment/Text/Comment/Static` marker symbols (same descriptions as Vue), `createVNode(type, props, children, patchFlag, dynamicProps, isBlockNode)` (props normalization: `class` via normalizeClass, `style` via normalizeStyle for reactive-object/array styles, proxies are `guardReactiveProps`-ed; type normalization for `Fragment`, components (object/function with `__vccOpts`), teleport/suspense markers, string tags; `key`/`ref` extraction incl. `ref_key`/`ref_for`; `shapeFlag` computation; `normalizeChildren` incl. slots objects and functions-as-default-slot), `createElementVNode`, `createBaseVNode` semantics, `createBlock`/`createElementBlock`, `openBlock/closeBlock/setupBlock/setBlockTracking`, dynamic-children tracking on block entry/exit exactly like Vue (`blockStack`, `currentBlock`, `isBlockTreeEnabled`, the `(patchFlag > 0 || shapeFlag & COMPONENT) && currentBlock` rule, the `CACHED` and `HYDRATE_EVENTS` special cases), `createTextVNode`, `createCommentVNode(text, asBlock)`, `createStaticVNode` (throws a clear unsupported TypeError: static HTML strings are not supported, the SFC options disable hoistStatic), `normalizeVNode` (null/boolean → Comment, array → Fragment, string/number → Text, mounted vnodes cloned), `cloneVNode` (props merging with `extraProps`, `mergeRef`), `cloneIfMounted`, `isVNode`, `isSameVNodeType`, `mergeProps(...)` (class/style/on merging; handlers into arrays; other keys override), `guardReactiveProps`, `transformVNodeArgs` is NOT exported, `deepCloneVNode`, `convertLegacyRefInFor`-equivalents only if the compiler can emit them.
   Expose `exports(rt) -> Vec<(&'static str, Value)>` for each module (names exactly as Vue's `vue` exports: `createVNode createElementVNode createElementBlock createBlock createTextVNode createCommentVNode createStaticVNode Fragment Text Comment Static openBlock setBlockTracking mergeProps isVNode cloneVNode normalizeClass normalizeStyle normalizeProps guardReactiveProps toDisplayString renderList createSlots toHandlers withMemo isMemoSame toHandlerKey camelize capitalize` …); `exports.rs` has `pub fn all(rt) -> Vec<(&'static str, Value)>` collecting every module's exports (later WPs add their lines) and `pub fn register_vue_module(rt)` (registers the native module `"vue"`; later WPs/aggregators extend it before registering — design `all()` to be callable once).
3. `normalize.rs`: pure helpers with exact Vue behaviour: `normalizeClass` (strings, arrays, objects, nested), `normalizeStyle` (objects, arrays, CSS text strings → objects via `parseStringStyle` with Vue's regexes/rules: `;` outside parentheses, `:` first occurrence, trimming), `stringifyStyle`, `normalizeProps` (class/style on props objects), `toDisplayString` (null/undefined → '', arrays/plain objects → `JSON.stringify(val, replacer, 2)` where the replacer unwraps refs (`__v_isRef` → value) and turns Map/Set into `{"Map(n)": {...}}`/`{"Set(n)": [...]}` forms and Symbols into strings, with the 3.5 handling; use the JSON builtin by calling the global `JSON.stringify` through the runtime (WP-B6 provides it; until it lands, test with a small native stand-in installed by the test) — and objects with a custom `toString` (non-Object.prototype.toString) via `String(val)`), `camelize/hyphenate/capitalize/toHandlerKey/isOn/looseEqual/looseIndexOf/looseToNumber/toNumber` (as used by directives). Expose to Rust and JS.
4. `helpers.rs`: `renderList(source, renderItem)` (arrays → `renderItem(item, index)`, numbers → `1..n`, strings → by code point? (Vue uses `Array(n)` + index: match it), iterables, objects (`renderItem(value, key, index)`), with the `cached`/`v-memo` argument form), `createSlots(slots, dynamicSlots)`, `toHandlers(obj, preserveCaseIfNecessary)`, `withMemo(memo, render, cache, index)` and `isMemoSame(cached, memo)`, `guardReactiveProps`. (Instance-dependent helpers — `renderSlot`, `withCtx`, `resolveComponent/Directive/DynamicComponent`, `withDirectives`, `withModifiers/withKeys` — belong to later WPs.)

## Tests (all expected values come from the real Vue 3.5.43 package run in Node)
- **Data-driven helper corpus:** extend `tooling/oracle/builtin-corpus.mjs` so a suite case may target `Vue.<name>` (resolved from a global `Vue` namespace object the generator installs from `require('vue')`; gate: the name must be a supported `vue` export in `compiler/profile` for origin `compiler` or `user`). Generate `tests/ui/runtime-a/corpora/helpers-*.json` (≥ 700 cases: normalizeClass/Style (strings, arrays, nested, objects, falsy parts, `{a:1,b:0}`), parseStringStyle edge cases (`;` inside `url()` and strings, comments `/* */`, missing values, trailing semicolons), toDisplayString (primitives, -0, NaN, arrays, nested objects, Map/Set, symbols, objects with custom toString, null/undefined, cycles → JSON error name), camelize/hyphenate/capitalize/toHandlerKey on tricky strings, mergeProps on pairs/triples (class/style/on* arrays, other keys), renderList on arrays with holes/numbers/strings/objects/Map/Set (with callback presets), toHandlers). Rust replay test `crates/runtime/tests/rta_helpers_replay.rs` using `vn_testkit::replay_suite` with a `ReplayOptions::setup` that installs the global `Vue` object from `exports::all`; **zero failures, zero missing**.
- **VNode shape corpus:** a Node generator `tests/ui/runtime-a/gen-vnodes.mjs` builds ≥ 250 VNode scenarios with real Vue (`createVNode`, `createElementVNode`, `createBlock`, `openBlock` sequences, `h`-style calls through the exported API only, fragments, text children, array children with nested blocks, slots objects, `ref`/`key`/`ref_for`/`ref_key`, patch flags, dynamicProps, `cloneVNode` with extra props, `mergeProps`, `normalizeVNode` on every input kind) and records a canonical JSON description of the resulting vnode (type tag, normalized props, key, ref (string|function marker), children kind and content (recursive), `shapeFlag`, `patchFlag`, `dynamicProps`, `dynamicChildren` length/kinds, `staticCount`, `appContext` null) — define the description in `tests/ui/runtime-a/README.md`. Rust side: `vnode::testing::describe(rt, &Value) -> String` + replay of the scenario programs (a small op language: each scenario is a list of `{call: "createElementBlock", args: […encoded…]}` steps with `$ref` to earlier results). Zero mismatches.
- Rust unit tests for flags, block stack misuse (closing with no open block), GC (vnodes reachable only via `dynamicChildren`/`children` survive collections), and a negative control per corpus family.
- Mutation check in a scratch copy (e.g. break the block-tracking rule and the class merge order → tests fail).
