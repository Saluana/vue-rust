## Part 1 — Promise (ECMAScript 2025, V8 ordering)
`Promise` (construct only; resolving functions with `already resolved` record; `length`/`name` exact), `Promise.prototype.then/catch/finally`, `Promise.resolve/reject/all/allSettled/race/any/withResolvers`, `AggregateError` (`errors`, `message`, `cause`), thenable assimilation via `PromiseResolveThenableJob`, `NewPromiseCapability` for the plain `Promise` constructor only (no species, no subclassing; `Symbol.species` absent), exact job counts/ordering (the number of microtask ticks between a resolution and its observers must equal V8's: e.g. resolving a promise with a native promise takes 2 extra ticks, `await nativePromise` takes 1, thenables 1 extra job, `finally` adds ticks, `Promise.all` element functions, `race`), unhandled-rejection bookkeeping per HTML's HostPromiseRejectionTracker: `Rt::take_unhandled_rejections() -> Vec<Value>` (promises rejected with no handler at the time of the call, in rejection order; a handler attached later removes it) and `Rt::set_rejection_tracker` hook if useful.
All handlers and reactions run as kernel jobs (`enqueue_job` with native functions holding their data) — nothing runs synchronously except the executor.

## Part 2 — Async function runtime (what the compiler's lowering of `async`/`await` calls; design is normative)
Compiled async functions are written by the compiler as Rust `async` blocks that keep **all locals and temporaries in a heap frame object** (never in Rust locals across an `.await`), so the collector (which only runs between jobs) can always see them. Provide:
```rust
pub fn new_frame(rt: &Rt, slots: usize) -> ObjRef;                    // heap object with `slots` Value slots (initially Undefined)
pub fn frame_get(rt: &Rt, f: ObjRef, i: usize) -> Value;  pub fn frame_set(rt: &Rt, f: ObjRef, i: usize, v: Value);
pub fn async_start(rt: &Rt, frame: ObjRef, body: Pin<Box<dyn Future<Output = Res<Value>>>>) -> Value;   // returns the result promise; runs the body synchronously up to its first await
pub fn await_value(rt: &Rt, v: Value) -> AwaitFuture;                 // `await v`: PromiseResolve(%Promise%, v) then PerformPromiseThen with continuation reactions; the future resolves with Ok(value) or Err(Throw) when the reaction job resumes the task
```
- The suspended task (`Pin<Box<dyn Future>>` + frame ref + result capability) lives in a heap Native object reachable from the pending promise reactions (traced) — an `await` on a promise that never settles must not leak the task once the promise itself is unreachable (test: collect + live-object count).
- Resumption happens ONLY from the promise reaction job (V8-identical ordering: `await` of a native promise costs exactly one tick; of a non-promise value one tick; of a thenable the thenable job + ticks per spec); use a no-op waker; never an external executor.
- `try/finally` and early returns are the compiler's business; you provide faithful `Err` propagation: a rejected awaited promise yields `Err(Throw(reason))` at the `.await?` site; the body's final `Ok(v)`/`Err(t)` resolves/rejects the result promise (value is `v`; if `v` is a promise/thenable the usual resolution procedure applies).
- Async arrow/methods share the same entry. `FnKind::Async` functions created by the compiler call `async_start`.
- Stack depth: a body polled from a job runs at call depth ≥ 1 (the kernel's `GC inside running code` guard must not trip, and `collect()` at depth 0 between jobs must see all frames).
