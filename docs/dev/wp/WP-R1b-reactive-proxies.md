## Implement
- Proxy-like objects as `ObjectKind::Exotic` with hooks `get/set/has/delete/own_keys/get_own_property/define` + `is_array` for array targets; `raw → proxy` caches (4 modes) in the **raw object's `ext` slot**; proxies hold the raw target strongly; flags readable via the special keys (`__v_isReactive`, `__v_isReadonly`, `__v_isShallow`, `__v_raw`, `__v_skip`) exactly like Vue (symbol-free string keys in prod); `Array.isArray(proxy)` true.
- Array methods are native function objects created once per realm and returned from the `get` hook for array targets (identity stable across reads, `proxy.includes === proxy.includes`); they call the real `Array.prototype` builtins with `this` = raw array (or proxy where Vue does) via the runtime's `call`. Map/Set: instrumentation as Vue (methods returned from the proxy's get; `size` getter; iterators wrapped to return reactive/readonly values; `forEach` callback wrapping).
- Replace R1a's identity `toReactive` hook with the real one; `ref` deep wrapping, `shallowRef`, `toRef(s)` over reactive objects, `isRef` unwrapping in reactive object reads (not in arrays' integer index reads, not for Map/Set elements) now behave per Vue.
- Exports (names/lengths as `vue`): `reactive shallowReactive readonly shallowReadonly toRaw markRaw isReactive isReadonly isProxy isShallow` (+ internal `toReactive toReadonly`), registered in the `exports()` list and in `testing.rs::register_vue_for_tests`.
