## Implement (production semantics; dev warnings omitted; no Suspense/Teleport/KeepAlive/Transition yet — leave clear hook points that throw `TypeError("unsupported: Teleport")`, RT-E fills them)
1. `renderer.rs`: `create_renderer(host)` / `Renderer` with `render(vnode|null, container)`, `patch` (type switch by `vnode.type`/`shapeFlag`), `mount_element` (props via `dom_props::patch_prop`, children, `setScopeId`/`slotScopeIds`, directives `created/beforeMount/mounted`, `needCallTransitionHooks` stubbed), `patch_element` (patchFlag fast paths: `FULL_PROPS`, `CLASS`, `STYLE`, `PROPS` with `dynamicProps`, `TEXT`, dynamicChildren via `patch_block_children`, `hasDirectives` hooks), fragments with anchors (`<!---->` start/end text nodes exactly as Vue), text/comment/static, `patch_children` (array/text/none transitions), `patch_unkeyed_children`, **`patch_keyed_children`** (5-step algorithm incl. `getSequence` LIS and `moved` handling), `move` (incl. component sub-trees, `MoveType`), `unmount` (refs, `onBeforeUnmount`, directives, `dynamicChildren` optimisation, `doRemove`, children, anchors, `unmountComponent` with scope stop, `onUnmounted` post-queue, `invalidateMount`), `remove` (host remove + release when safe), `get_next_host_node`, `queue_post_render_effect` (via scheduler post queue), `set_ref` calls, `hydrate` NOT here. Host nodes are `HostNode`; `vnode.el`/`anchor`/`target` store them. All Rust-side per-vnode/instance data must be traced by the collector (they live in heap Native objects).
2. `component.rs` + `props.rs` + `emits.rs` + `slots.rs` + `public_instance.rs`: `mount_component` (create instance via RT-B's `instance.rs`, `setup_component`: `init_props`, `init_slots`, `setup_stateful_component` (call `setup(props, ctx)` under `setCurrentInstance`, pause tracking, sync result: object → `proxyRefs`, function → render; async setup unsupported → TypeError), `finish_component_setup`: template/render resolution — compiled SFCs provide `render` or return a render function from setup (inline template mode): both paths; `inheritAttrs`), `setup_render_effect` (ReactiveEffect with `allowRecurse`, job queue with the instance uid, `onBeforeMount/onMounted/onBeforeUpdate/onUpdated` ordering, `updateComponentPreRender`, `renderComponentRoot` incl. attrs fallthrough merge for single-root/`inheritAttrs`, `filterSingleRoot`, `cloneVNode` with extra props, class/style/listener merge rules, directives/transition inheritance), `update_component`/`should_update_component` (props/children/dirs/patchFlag rules), props: normalization of runtime declarations (array and object forms, `type`, `required`, `default` incl. factory, `validator` ignored in prod, boolean casting incl. `''` and hyphenate rules, camelize keys, `$`-prefixed reserved keys), `init_props/update_props` (reactive `shallowReactive` props object, `attrs` extraction, `rawProps` with `PROPS`-flag optimisation, `isEmitListener` skipping, `__v_isRef`-aware), emits (`emit()` with `update:`/`onUpdate:` conventions, modifiers `.trim/.number` via `modelModifiers`, `once`, handler lookup camelize/hyphenate rules, array handlers, error handling), slots (`init_slots/update_slots`, object/array/function slot children, `_` flag semantics STABLE/DYNAMIC/FORWARDED, `normalizeSlotValue`, `withCtx` rendering-instance restore), `public_instance`: `PublicInstanceProxyHandlers` as an exotic `_ctx` (`$props $attrs $slots $emit $el $refs $parent $root $options(empty object) $forceUpdate $nextTick`; access cache; setupState/props/ctx lookups; set rules; `has`), `exposed`/`exposeProxy` and `getComponentPublicInstance`.
3. `setup_helpers.rs`: `useSlots`, `useAttrs`, `mergeDefaults`, `mergeModels`, `createPropsRestProxy`, `useModel` (the 3.5 implementation with `customRef`, local/parent sync, modifiers), `defineExpose` runtime hook via `expose()` in setup context, `useTemplateRef`, `withDefaults` is compile-time; `renderSlot`, `resolveComponent/resolveDirective/resolveDynamicComponent` (against `appContext` + the instance's `components`/`directives` + `__name`/self-reference), `createSlots` is RT-A's. `refs.rs`: `set_ref` (string refs → `refs` + setupState writes, function refs, ref objects, `ref_for` arrays, `unmount` nulling, post-flush timing `queuePostRenderEffect` with `id=-1`). `directives.rs`: `with_directives`, `invoke_directive_hook` with binding `{instance,value,oldValue,arg,modifiers,dir}`; `resolve_directive`.
4. `app.rs`: `create_app(root_component, root_props)` returning an app object with `mount(container)`, `unmount()`, `use(plugin, ...opts)` (function or `{install}`; idempotent), `component(name[, def])`, `directive(name[, def])`, `provide(key, value)`, `runWithContext`, `version`, `config.{errorHandler, warnHandler (ignored), globalProperties (rejected: TypeError unsupported), performance, compilerOptions (ignored/error), throwUnhandledErrorInProduction}`, `onUnmount`; `mount` takes a **`HostNode` container or a selector string** (resolved through `Host::query_selector`) and uses `Renderer::render`; `app._context` internals. Export `createApp` (+ `createVNode`-family from RT-A are already exported), `defineComponent` (identity for objects/functions), `withCtx renderSlot resolveComponent resolveDirective resolveDynamicComponent withDirectives useSlots useAttrs useModel mergeDefaults mergeModels createPropsRestProxy useTemplateRef` etc., via `exports.rs` (repo edit).
5. Error handling in render/setup/lifecycle uses RT-B's `call_with_error_handling`; render errors produce a Comment vnode like Vue (`createVNode(Comment)` fallback) after `handleError`.
