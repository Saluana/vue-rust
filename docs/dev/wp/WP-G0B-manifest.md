# WP-G0B — Compatibility manifest and Vue export audit (tasks.md 2.2)

Read `docs/dev/AGENT-CONTRACT.md` first. WP id: `g0b` (no cargo needed).

**Owned paths:** `compiler/profile/**` (new directory; do NOT touch `compiler/compile.mjs`/`cli.mjs`),
`tooling/manifest/**`, `tests/profile/**`, `docs/compatibility/**`.

## Why
The language/Vue/TS profile is **closed-world and default-deny** (design.md §8). Every construct and API needs a
machine-readable status so the compiler can accept, adapt or reject it with a precise diagnostic, and so no
support claim exists without an owner and a test family (requirements R01.AC1).

## Inputs
- `planning/vue-native-framework/design.md` §8.1–§8.5 (tables with row IDs L01–L21, S01–S25, V01–V29, U01–U32,
  A01–A19 = **126 rows**). Row columns differ by section: §8.1–8.4 are `ID / name | Status; prototype | contract |
  tests/exclusions`; §8.5 is `ID / surface | Proposed status and treatment | Required case`.
  Status letters: **P** faithful, **A** adaptation, **W** web-only, **X** excluded (must error), **E**
  experimental. Prototype letters: **C** counter, **Q** quote, **—** none. Some rows combine statuses
  (e.g. `A native/P DOM`, `X native/shared, E web`, `P subset`) — keep the verbatim text AND derive the set.
- The real pinned package: `node_modules/vue` (3.5.43) and its `@vue/*` dependencies.

## Do
1. `tooling/manifest/extract-inventory.mjs`: parse the design.md tables (markdown parser written by you; no new
   deps) into `compiler/profile/inventory.generated.json`: per row `{ id, section, title, statusText, statuses[],
   primary, prototype, contract, tests, rawRow }`. Fail loudly if the ID set is not exactly the expected 126.
2. `compiler/profile/expansions.json`: hand-authored (by you, from the design text) expansion of grouped rows into
   individually named API/construct entries, e.g. V09 → `isProxy,isReactive,isReadonly,isShallow`; A11 → `h,
   mergeProps, cloneVNode, isVNode, resolveComponent, resolveDirective, withDirectives, withModifiers`; U-rows →
   directive/component names; S-rows → macro names (`defineProps`, `withDefaults`, `defineEmits`, `defineModel`,
   `defineExpose`, `defineOptions`, `defineSlots`). Each entry: `{ name, kind, row, status, note? }`.
3. `tooling/manifest/audit-vue-exports.mjs`: enumerate the **real** runtime exports of `vue` 3.5.43
   (`Object.keys(await import('vue'))`) plus the compile-time macros from `vue`'s type declarations, and classify
   each export into exactly one row via `compiler/profile/export-map.json` (authored by you). Output
   `compiler/profile/vue-exports.json` and a human report `docs/compatibility/vue-exports-audit.md`. Required
   outcome: **zero unclassified exports**. If an export has no clear row, classify it `X` with
   `note: "unclassified: default-deny"` AND list it in a report section "Needs maintainer decision". Explicitly
   record whether `isShallow` is exported by the pinned package (design.md says this must be checked) and any
   documented API that is absent from the pinned package (docs drift).
4. `compiler/profile/manifest.json` (generated by `tooling/manifest/build-manifest.mjs`): `{ schemaVersion: 1,
   vueReference: "3.5.43", default: "deny", rows: [...], entries: [...], vueExports: [...] }` and
   `compiler/profile/index.mjs` exporting `loadManifest()`, `lookup(kind, name)` → `{status,row,note} | null`
   and `isSupported(kind, name)` (true for P/A/W per target argument; X/E/unknown false). Unknown → null.
5. `docs/compatibility/README.md` (what statuses mean, how to regenerate) and `docs/compatibility/inventory.md`
   (generated human-readable table of all rows with status).
6. Tests in `tests/profile/*.test.mjs` (node:test): exact ID set and count; every row has a valid status; every
   `vue` runtime export is classified; `lookup('vue','definitelyNotAnExport')` is null; default-deny holds;
   the extractor fails on a mutated copy of the design text with one row removed (negative control, use a temp
   file); regenerating the manifest twice yields byte-identical output (determinism).

## Acceptance
`node --test "tests/profile/*.test.mjs"` passes; `node tooling/manifest/build-manifest.mjs` is deterministic; the audit report
has no unclassified exports; no files outside owned paths changed.
