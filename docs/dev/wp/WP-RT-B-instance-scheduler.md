## Implement (production semantics; dev-only warnings omitted)
1. `instance.rs`: the `ComponentInstance` record as a heap `Native` object with interior mutability and the **full field set** of Vue's `ComponentInternalInstance` (uid, vnode, type, parent, appContext, root, next, subTree, effect/update/job, scope, provides, ids, accessCache, renderCache, components/directives, propsOptions, emitsOptions, emit, setupState, setupContext, props, attrs, slots, refs, exposed/exposeProxy, ctx, inheritAttrs, isMounted/isUnmounted/isDeactivated flags, lifecycle hook arrays `bc c bm m bu u um bum da a rtg rtc ec sp`, asyncDep/asyncResolved, `n` and `u` job slots, `suspense` as unsupported marker, …) plus `current_instance`/`current_rendering_instance` state in an `Rt`-attached runtime state object (root-provider registered, GC-traced), and the `set/unset/get_current_instance`, `set_current_rendering_instance`, `with_instance(instance, f)` helpers. The renderer WP (RT-C) fills and uses it: document each field's owner/lifetime in the module header.
2. `scheduler.rs`: the exact 3.5 job queue: `queue_job` with id-ordered insertion (`findInsertionIndex`, `PRE` flag, `ALLOW_RECURSE`, `QUEUED`/`DISPOSED` flags), `queue_post_flush_cb`, `flush_pre_flush_cbs`, `flush_jobs` (recursion check count in prod = none, but keep the `RECURSION_LIMIT` watchdog as a resource error), `flush_post_flush_cbs`, the "currentFlushPromise/resolvedPromise" mechanics using the kernel job queue + `Promise` builtin (B5), `next_tick(fn?)` returning a real promise (`p.then(fn)` form per Vue), `queueFlush`. Ordering of jobs relative to user promise jobs must equal Vue's (V0 scenarios under `tests/vue/cases/scheduler/*` and `watch/*` are the oracle).
3. `watch.rs`: `watch`, `watchEffect`, `watchPostEffect`, `watchSyncEffect` (`doWatch` with `flush: 'pre'|'post'|'sync'`, instance-aware scheduling: pre jobs are queued with the instance uid as id, `immediate/once/deep/ (number depth)/onCleanup`, `onWatcherCleanup`), built on `vn_reactivity::watch_base`; `WatchHandle` with `stop/pause/resume`; `this`-less forms only; error handling via `call_with_error_handling` with `WATCH_GETTER/WATCH_CALLBACK/WATCH_CLEANUP` types.
4. `errors.rs`: `call_with_error_handling`, `call_with_async_error_handling` (promise results get a `.catch` that routes to `handle_error`), `handle_error` (walk parents' `onErrorCaptured` hooks, `app.config.errorHandler`, then `log_error`), `log_error` in production = report to a host sink (`Rt`-level `ErrorSink` that tests install; default prints to stderr) **without rethrowing** unless `throwUnhandledErrorInProduction` is configured; error type strings table (`ErrorCodes`).
5. `lifecycle.rs`: `inject_hook` (wraps the hook with `setCurrentInstance` and error handling, `prepend` support), all `onX` registration functions as native functions with Vue's names/lengths, `onErrorCaptured`, `onServerPrefetch` (stored only), `onRenderTracked/onRenderTriggered` (no-ops accepting a function); registration outside an instance is a no-op in production (Vue warns in dev only).
6. `inject.rs`: `provide` (creates `Object.create(parentProvides)` lazily like Vue), `inject(key, default, treatDefaultAsFactory)`, `hasInjectionContext`, app-level provides via `appContext.provides`, `useId` (instance-scoped counter `prefix + ':' + ids`), `getCurrentInstance` (returns the instance's *public* representation or the internal handle — document; expose the internal record, the renderer's public proxy is RT-C).
7. Exports: `watch watchEffect watchPostEffect watchSyncEffect nextTick provide inject hasInjectionContext getCurrentInstance onBeforeMount onMounted onBeforeUpdate onUpdated onBeforeUnmount onUnmounted onActivated onDeactivated onErrorCaptured onServerPrefetch onRenderTracked onRenderTriggered useId` (names as in the manifest), registered through `exports.rs`.
