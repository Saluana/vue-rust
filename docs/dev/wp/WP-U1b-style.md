# WP-U1b — `vn-ui` style: typed values, shorthands, computed style, UA stylesheet

Read `docs/dev/AGENT-CONTRACT.md`, `docs/dev/ARCHITECTURE.md` §4, design.md §9.2 (CSS contract), `crates/css/src/support.rs`, and skim `crates/css` and `crates/dom` APIs.
`export CARGO_TARGET_DIR="$VN_ROOT/target/u1b"`. Oracle = headless Chrome through `tooling/chrome` (`withPage`, README).
**Owned paths:** new crate `crates/ui/**` (package `vn-ui`, library `vn_ui`; deps: `vn-css`, `vn-dom` by path; **std only otherwise**, no `unsafe`), `tests/ui/style/**`.
Create `Cargo.toml` and `src/lib.rs` in the same command (workspace glob).

## Why
Rendering needs typed style values, not tokens. This WP turns cascaded declarations (WP-U1a) over a `vn-dom::Document` into a `ComputedStyle` per element for the **documented property subset** (allowlist = design.md §9.2).
Unsupported properties/values produce diagnostics (never silent). The web target uses the browser; Chrome is the oracle for what the subset *means*. Layout and painting are the next WPs and consume your output.

## Deliver
1. `values`: typed CSS values and parsers from `vn_css` token lists: `Length` (px, em, rem, vw, vh, vmin, vmax, %, unitless 0, `calc()` of lengths/percentages with + − × ÷ and nested parens; resolved lazily against font size/viewport/containing size), `Color` (named colours — all 148 CSS named colours + `transparent`, `currentcolor`, `#rgb[a]`, `#rrggbb[aa]`, `rgb()/rgba()` legacy and space syntax with `/ alpha`, `hsl()/hsla()`, `color-mix` NOT supported → diagnostic), `Number`, `Integer`, `Keyword` enums per property, `Percentage`, `Time` (for transitions later: parse only), font-family lists (quoted/unquoted, generic families), `Display`, `Position`, flex/grid values (tracks: `px %, fr, auto, minmax(), repeat(n|auto-fill|auto-fit, …), min-content/max-content` — parse and represent; layout is the next WP), `Transform` (2D: translate/scale/rotate/skew/matrix, perspective rejected).
2. `props`: the property table: name → `{ inherited, initial, grammar, longhands? }` for the allowlist: box model (`display position top right bottom left inset width height min-width max-width min-height max-height margin* padding* border* box-sizing overflow overflow-x overflow-y z-index opacity visibility`), flex (`flex flex-grow flex-shrink flex-basis flex-direction flex-wrap flex-flow justify-content align-items align-self align-content gap row-gap column-gap order`), grid (`grid-template-columns grid-template-rows grid-template-areas(E) grid-column grid-column-start grid-column-end grid-row grid-row-start grid-row-end grid-auto-flow grid-auto-columns grid-auto-rows justify-items justify-self place-items place-self place-content`), text (`color font font-family font-size font-weight font-style line-height letter-spacing text-align text-decoration text-decoration-line text-transform white-space text-overflow overflow-wrap word-break vertical-align`), painting (`background background-color border-radius* outline* box-shadow(E: parse + diagnostic 'not rendered yet') cursor pointer-events user-select transform(2D) object-fit aspect-ratio`), and custom properties. Everything else → diagnostic VNCSS5xxx with the property name and hint. **Shorthand expansion** (`margin padding border border-* border-radius flex flex-flow gap place-* inset font background overflow outline text-decoration grid-column grid-row`) into longhands with exact CSS semantics (1–4 values, `none`, `inherit`, `initial`, `unset`, `revert` → treat as `unset` with a diagnostic).
3. `computed`: `compute_styles(doc: &Document, sheets: &[Sheet], env: &MediaEnv, viewport) -> StyleTree` using `vn_css::cascade` with an `Element` adapter over `Document` (implement the `vn_css::Element` trait for a document-element view; state flags from focus/hover/active/checked/disabled maintained by the caller via a `StateProvider`), inheritance of inherited properties, initial values, `var()` substitution (custom properties inherited), `em/rem/%` handling at compute time per spec (percent lengths stay percentages for layout), `currentcolor` resolution, `font-size` keywords/relative (`smaller`/`larger`), `line-height` number vs length, `font-weight` keywords incl. `bolder/lighter`, `display: contents/none` handling, inline `style` attribute declarations as highest-priority normal declarations. Output `ComputedStyle` (typed struct) per element with `get(&str)` debug accessor producing Chrome-like serialisations for the oracle comparison.
4. `ua`: the built-in user-agent stylesheet for the supported tags (block display for div/section/main/header/footer/nav/article/aside/form/ul/ol/li/hr/h1–h6/p/pre; margins and font sizes/weights for h1–h6, p, ul/ol padding, `strong/b` bold, `em/i` italic, `code/pre` monospace family, `a` colour+underline, `button/input/textarea/select` default padding/border/background/cursor, `hr`, `label`, `img` inline-block, `[hidden] {display:none}`), written as CSS text parsed by `vn-css` at startup — mirror Chrome's defaults for these (compare with `getComputedStyle` in the oracle; document intentional deviations).
5. `diagnostics`: a `StyleDiagnostic` list (unsupported property/value/function, with span if from a stylesheet).

## Oracle & tests (`tests/ui/style/gen/*.mjs` → `tests/ui/style/corpora/*.json`, Rust tests in `crates/ui/tests/`)
- **Values**: ≥ 600 (property, specified value) pairs per category (lengths, colours, keywords, shorthands, calc, font-family, transform) run through Chrome: set on an element in a fixed context (known font-size 16px, known viewport 800×600, parent font-size 20px), read `getComputedStyle(el).<longhand>` and record the Chrome-serialised value; Rust parses + computes in the same context and compares via the Chrome-like serialiser (colours `rgb(r, g, b)`/`rgba(r, g, b, a)` forms, lengths `Npx`, percentages kept). Invalid values: Chrome ignores → we emit a diagnostic and keep the inherited/initial value; compare the computed result.
- **Cascade+inheritance fixtures**: ≥ 60 small documents (inheritance of color/font-*, em compounding, rem, vw, var() chains with fallback, !important, media rules, inline style, state pseudo-classes via attributes `disabled`/`checked`) compared on ≥ 10 properties each.
- **UA defaults**: for every supported tag, compare ~25 computed properties with Chrome.
- Unit tests for parsers' edge cases and diagnostics; determinism of generators; negative control.

## Acceptance
`cargo test -p vn-ui` green, no warnings, generators deterministic, Chrome processes cleaned up; a table in your report of corpora sizes and any intentional deviations from Chrome with reasons.
