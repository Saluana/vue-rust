## Deliver
1. `vue-native check <entry.vue|dir>`: SFC + profile + stdlib diagnostics through `compileProject`/`compileSfc` with `formatDiagnostic` output, non-zero exit on errors, `--json`; `vue-native build --target web|headless <entry> --out <newdir>` (refuses an existing output dir, like the prototype CLI; writes a tool-owned manifest so reruns are safe only into tool-owned dirs): compileProject → generated crate (`Cargo.toml` with path deps on the framework crates located via `VN_FRAMEWORK_ROOT`/the repo root, `modules.rs`, app entry) → `cargo build --release --target wasm32-unknown-unknown` (web) → output dir with content-hashed `.wasm`, `vn-host.js`, `index.html`, `manifest.json`, CSS from `<style>` blocks (scoped CSS is already transformed by compileSfc; inject as a `<style>` element or file); `headless` builds a native binary that mounts the app in a `DocHost`, runs a scripted interaction file (JSON) and prints snapshots (for tests); `vue-native create <dir> [--template counter]`; `vue-native doctor` (reports missing toolchain pieces, no installs); `--help`.
   The web app entry: a generated `lib.rs` (cdylib) re-exporting `vn_renderer_dom`'s ABI exports (`pub use` so they survive linking — verify with `wasm-objdump`-free means: parse the export section in a Node test) plus `vn_start` that creates the realm, installs `WebHost`, registers the `vue` native module (`vn_runtime::exports::register_vue_module`), loads the project modules (`defs()` table) and mounts the root component into `#app` (container selector from the manifest).
2. Demos: `examples/counter` (the Counter.vue behaviour of the prototype: count/doubled/reset/disabled/v-if), `examples/quick-quote` (a quote form with a reusable field child component, `computed` total, `watch`, `v-for` keyed lines (2 items), numeric input validation message, add/remove line items, unmount/recreate toggle, `defineProps/defineEmits/defineModel`, TypeScript `lang="ts"`; money in integer cents with explicit decimal formatting via `toFixed`; no persistence yet). Both must compile with `vue-native check`.
3. **End-to-end tests in real Chrome** (`tests/platform/web/e2e-*.test.mjs` using `tooling/chrome`): build each demo, serve the output dir, load it, assert the initial DOM, click/type like a user (CDP input events or `page.evaluate` dispatch of real events), assert DOM after each step, check no console errors, measure and print wasm size + time-to-first-render. The Counter e2e is the first acceptance target; Quick Quote second.
4. `docs/guide/getting-started.md` (accurate, short: prerequisites, `check`, `build`, serve, edit loop) written from what you actually ran.
