Read `docs/dev/AGENT-CONTRACT.md`, `docs/dev/ARCHITECTURE.md` §4, **`crates/runtime/src/host.rs`** (the `Host`/`EventSink` contract you implement; coordinator-owned — propose changes in your report, don't edit it),
`tooling/chrome/README.md` + `chrome.mjs`, and skim `crates/dom/src/*.rs` (the Rust in-memory DOM that implements the same contract for headless/native hosts: your glue must behave like a real browser, which `vn-dom` mimics).
WP id `w1a`; `export CARGO_TARGET_DIR="$VN_ROOT/target/w1a"`. Create `Cargo.toml` **and** `src/lib.rs` of a new crate in the same command (workspace glob).
**Owned paths:** new crate `crates/renderer-dom/**` (package `vn-renderer-dom`, library `vn_renderer_dom`, `crate-type = ["rlib","cdylib"]`; depends on `vn-runtime` by path for the `host` module types only — add the dependency line; `vn-value` if needed),
`hosts/web/**` (generated-or-handwritten JS glue + html shell), `tooling/web/**` (build scripts), `tests/platform/web/**`.
**`unsafe` is allowed in this crate ONLY inside `src/ffi.rs`** (wasm imports/exports and linear-memory buffers); every `unsafe` block needs a `// SAFETY:` comment; the rest of the crate is `#![deny(unsafe_code)]` with a module-level allow on `ffi`.

## Why
The web target runs the same compiled Rust (WASM) with **semantic DOM** controls (no canvas): the Rust side drives the real DOM through a thin import table. No wasm-bindgen, no framework: you hand-write both ends so the boundary is auditable and small.

## Deliver
1. **Boundary ABI** (document it in `hosts/web/ABI.md`, versioned `abiVersion: 1`, checked at start-up by an exported `vn_abi_version()` and a JS constant — mismatch = hard failure with a clear message):
   - Exports from wasm: `memory`, `vn_alloc(len)->ptr`, `vn_free(ptr,len)`, `vn_abi_version()`, `vn_event(listener_id, ptr, len)->outcome_bits` (event payload = fixed little-endian struct you define: type/key/code/data string offsets, f64 timestamp/clientX/clientY, i32 button/detail/phase, flags for bubbles/cancelable/composed/defaultPrevented/ctrl/shift/alt/meta/isComposing; target and currentTarget node ids), `vn_timer(id)`, plus feature-gated `selftest_*` entry points.
   - Imports (module `"vn_host"`): one per `Host` method, scalar and `(ptr,len)` UTF-8 arguments only; results by return value or by out-pointers; strings returned by JS are allocated with the exported `vn_alloc` and freed by Rust; `host_now()`, `host_set_timeout(id, ms)`, `host_clear_timeout(id)`, `host_log(level, ptr, len)`, `host_panic(ptr,len)`.
   - Node ids: JS keeps `nodes[]` + free list; id 0 = none; `release` frees; using a released/unknown id returns `HostError::NotFound`/`InvalidState` (never a JS exception crossing into Rust).
2. **Rust side** `WebHost` implements the whole `Host` trait; `EventSink` wiring: `vn_event` looks up the registered sink and returns the outcome bits (stop propagation / immediate / prevent default / threw) that the glue applies to the real event **synchronously**. Re-entrancy must work (a listener, called from inside `insert`/`remove`/`focus`, calls back into the host). Map `HostError`s from JS return codes. No panics across the boundary: install a panic hook calling `host_panic`.
3. **JS glue** `hosts/web/vn-host.js` (ES module, no dependencies, ≤ ~600 lines, readable): `createHost({ document, wasmBytesOrUrl, onLog })` → instantiates, wires imports to the DOM (`createElement/NS`, text/comment nodes, `insertBefore`, `removeChild`, attributes (NS aware), property get/set with the five `HostValue` kinds and DOM coercion exactly as `el[name] = v`, `style.setProperty/removeProperty/getPropertyValue/cssText`, `classList`, `addEventListener` with `{capture,once,passive}`, focus/blur/activeElement, `querySelector`, `outerHTML/innerHTML`, `option` list for `select`), event listener closures that pack the event and call `vn_event`; microtask/timers via the host timer imports; a `destroy()`. Provide `hosts/web/index.html` shell and a `tooling/web/build-wasm.mjs` that runs `cargo build --release --target wasm32-unknown-unknown -p vn-renderer-dom` (honouring `CARGO_TARGET_DIR`), copies the `.wasm` + glue to an output dir with a content-hash name and a manifest `{abiVersion, wasm, hash, bytes}`; print the wasm size.
4. **Self-test wasm**: feature `selftest` adds exported functions that exercise the `Host` trait from Rust and report back through a result buffer/JSON (e.g. `selftest_run(name_ptr,len)->ptr`); no Vue yet.

## Tests (real Chrome through `tooling/chrome`; `serveDirectory` for the wasm + glue; skip LOUDLY if Chrome is missing)
`tests/platform/web/*.test.mjs`, ≥ 60 cases with hand-written expectations checked against the real DOM state read back from the page: every Host method (tree ops incl. move/anchor errors, text/comment, textContent replace, attributes incl. NS and case rules, properties of all five value kinds, `value`/`checked`/`selected`/`disabled` semantics, style ops and cssText round trip, classList, selectors, focus/blur events order, `option_nodes`, serialization), events (every option combination, bubbling/capturing order across nested nodes, `once`, `passive`+preventDefault ignored, stopPropagation/stopImmediatePropagation from Rust, preventDefault effect on real `defaultPrevented`, listener throwing in Rust → reported and dispatch continues, event data fidelity incl. Unicode `key`, composition flags, timestamps), re-entrancy (listener removes the node being inserted, blur fires during remove), strings (empty, 1 MB, astral chars, embedded NULs), id exhaustion/reuse after release, memory growth stability over 50 000 create/insert/remove/release cycles (assert wasm memory pages stop growing), ABI mismatch detection, a panic in Rust is reported and the page keeps working for other calls. Negative control: break one import in a scratch copy → at least one test fails.
**Cross-implementation conformance (do this if `vn_dom::Document` has a `Host` impl by then — check `crates/runtime/src/`; otherwise write the replay driver generically and leave it unused):** the Chrome-recorded op corpora in `tests/dom/corpora/*.json` (see `tests/dom/gen/README`/builder.mjs for the op language) can be replayed through any `Host`; add `tests/platform/web/replay-dom-corpus.test.mjs` driving the selftest wasm with the same op lists and comparing the resulting snapshots with the recorded Chrome ones.
