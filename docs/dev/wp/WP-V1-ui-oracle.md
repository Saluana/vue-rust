# WP-V1 — Component/UI oracle: real Vue in headless Chrome + scenario corpus

Read `docs/dev/AGENT-CONTRACT.md`, `docs/dev/trace-format.md`, **`docs/dev/ui-scenario-host.md`** (the contract you implement on the oracle side), `compiler/sfc/index.mjs` (WP-F1, done),
`tooling/chrome/README.md` + `chrome.mjs` (WP-X1), `tooling/oracle/{trace,node-runner,compare,vue-env}.mjs`, `tests/vue/cases/README.md`, and `crates/dom/src/{serialize,props}.rs` (the Rust DOM whose snapshot rules you must reproduce in the browser). WP id `v1`; no cargo.
**Owned paths:** `tooling/oracle/ui/**`, `tests/ui/cases/**`, `tests/ui/golden/**`, `tests/ui/oracle.test.mjs`, `tests/ui/README.md`.
Dependencies: only the installed packages (`vue@3.5.43` browser build `node_modules/vue/dist/vue.global.prod.js`, compiler-sfc via `compiler/sfc`). Close every Chrome process you start.

## Why
Our Rust runtime (`vn-runtime`: a port of Vue's `runtime-core` renderer + `runtime-dom` prop/event logic over `vn-dom`) will be verified by running the **same compiled JavaScript** in two engines and comparing traces (rendered DOM snapshots, lifecycle order, event effects). You build the oracle: the real Vue in a real browser DOM, plus the first corpus of scenarios.

## Do
1. **Oracle runner** `tooling/oracle/ui/run-ui.mjs`: `runUiScenario(dir) -> Promise<Document>` (trace-format document). It
   - compiles every `.vue` imported by `scenario.js` with `compileSfc` (target `native`, deterministic ids) and serves the results as ES modules from a tiny Node HTTP server (also serves `scenario.js`, an import map mapping `'vue'` to a shim module that re-exports the members of the global `Vue` loaded from `vue.global.prod.js`, and the page host);
   - launches headless Chrome via `tooling/chrome` (fresh profile, 800×600), loads a blank page that installs: fake clock (`Date.now`, `performance.now`, `setTimeout`, `clearTimeout`, `requestAnimationFrame` all driven by the same deterministic clock `testHost.timers`), globals `trace` and `testHost` per ui-scenario-host.md / trace-format.md (the JS trace encoder must be the **same code as `tooling/oracle/trace.mjs`**: load it into the page as a module — if it uses Node-only APIs, refactor by *copying logic into a browser-safe module in your owned path* and add a test that both encoders produce identical output on ≥ 25 graphs);
   - implements `testHost.mount/find/findAll/click/input/change/check/select/keydown/focus/dispatch/tick` and the `Mount`/`NodeHandle` objects on the real DOM (events dispatched with real `Event`/`MouseEvent`/`KeyboardEvent`/`InputEvent` objects with `bubbles:true, cancelable:true` as a user would produce; `input()` sets `.value` then dispatches `input`; `check()` performs a real `.click()`), and the canonical element snapshot with the **exact rules** of ui-scenario-host.md (read `el.attributes` in order; `props` only for value/checked/selected/disabled when they differ from the attribute-derived default — define precisely how "attribute-derived default" is computed, matching `crates/dom/src/serialize.rs`; adjacent text nodes not merged; comments included);
   - runs the scenario module (module evaluation, then drain, then `run()`, then drain, as in trace-format.md), collects the document, closes Chrome and the server, and returns it. One browser per scenario is acceptable (≈0.5 s); allow batching several scenarios per browser session if you can keep full isolation (fresh page/realm per scenario).
2. `tooling/oracle/ui/check-goldens.mjs` (`--update`, `--filter`), golden path `tests/ui/golden/<group>/<name>.json` (one line, exactly the document), deterministic regeneration (run twice → identical bytes).
3. **Corpus**: ≥ 140 scenarios under `tests/ui/cases/<group>/<name>/{scenario.js,*.vue}` with header tags `// @tier N` / `// @covers U14,V18` (IDs from design.md §8.3/8.4 and the manifest). Groups (adapt names): `static` (elements, text, comments, whitespace condense, attributes, boolean attrs, class/style bindings incl. object/array syntax and merging, `v-bind` object spread, `v-text`, `v-once`, `v-pre`, `v-cloak`, `v-show`), `conditional` (`v-if/else-if/else`, `v-show`, fragments, comment placeholders `<!--v-if-->`), `list` (`v-for` over arrays/objects/ranges/strings with and without keys, reorder/insert/remove/move preserving DOM identity (use a `data-id` marker and `testHost`-side identity check via `snapshot` order + a `ref` to the elements that scenarios compare before/after through `el === el` booleans traced), nested lists, `v-for`+`v-if`), `events` (click/keyboard/input with modifiers `.stop .prevent .self .once .capture .exact .left .middle .right .enter .esc .ctrl…`, inline handlers, handler caching, `$event`, event order bubbling through nested components), `model` (`v-model` on text/textarea/checkbox (boolean, array, true/false-value)/radio/select (single, multiple)/range? NO — number input via `.number`, modifiers `.lazy .trim .number`, composition events `compositionstart/end`, `defineModel` parent/child), `props` (types, defaults, required, boolean casting, `withDefaults`, destructured props, readonly warnings are dev-only — skip, attrs fallthrough, `inheritAttrs:false`, `$attrs` merging of class/style/listeners), `emits` (declared vs undeclared, payloads, `.once`, `v-model:foo`), `slots` (default, named, scoped, dynamic names, fallback content, `v-slot` destructuring, `$slots` in script, conditional slots, slot props reactivity), `provide-inject` (nearest provider, defaults, factory defaults, symbol keys, reactivity), `lifecycle` (order of `onBeforeMount/onMounted/onBeforeUpdate/onUpdated/onBeforeUnmount/onUnmounted` across parent/child/siblings and `v-if` toggles, `onRenderTracked` absent in prod), `refs` (template refs on elements/components, `v-for` refs, function refs, `useTemplateRef`, `defineExpose`), `watch-in-component` (flush modes relative to render and `onUpdated`), `errors` (`onErrorCaptured`, `app.config.errorHandler` via `testHost.mount(comp, props, { errorHandler })` option — document the option), `dynamic` (`<component :is>`, `KeepAlive` include/exclude/max with `onActivated/onDeactivated` and state preservation, `defineAsyncComponent` with loader promise via `testHost.timers`), `teleport` (to `body`/`#id` created by the scenario in the page via `testHost.container('id')`, `disabled`, `defer`), `transition` (hook order with `testHost` fake clock; class names applied; `mode="out-in"`; FLIP not needed) — keep Transition scenarios few and only for behaviours independent of real CSS timing (use `css:false` with JS hooks), `fragments` (multi-root, text roots, comment roots), `directives` (custom directive hooks order and arguments; `v-model` on component), `scoped-css` (data-v attributes only), `ssr-hydrate` NOT here.
   Every scenario uses only profile features (same lint as WP-O1/V0 plus Vue UI APIs from the manifest), traces **snapshots and plain data only** (never proxies/DOM nodes), and uses no real time. Goldens are generated by the oracle you wrote (real Vue + real DOM); review a sample of 10 goldens by hand against your understanding of Vue and say which.
4. **Tests** `tests/ui/oracle.test.mjs`: harness behaviours with hand-written expectations (each testHost API; snapshot rule table incl. dirty `value`/`checked` props, comments, adjacent text nodes; fake clock ordering; event dispatch realism: bubbling, `defaultPrevented`, modifiers; error cases), determinism (twice → identical), isolation between scenarios, the encoder-equivalence test, negative control (doctored golden detected), golden check for all scenarios, and a lint pass over all cases. All Chrome processes closed at the end.

## Acceptance
`node --test "tests/ui/oracle.test.mjs"` passes (incl. all goldens); `node tooling/oracle/ui/check-goldens.mjs` → all match; regeneration byte-identical; report the group counts and the 10 hand-reviewed goldens.
