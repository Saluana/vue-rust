**Owned paths:** new crate `crates/reactivity/**` (package `vn-reactivity`, library `vn_reactivity`; deps: `vn-value` by path; std only otherwise; `#![forbid(unsafe_code)]`), `tests/vue/rust/**`.
Create `Cargo.toml` and `src/lib.rs` in one command (the workspace globs `crates/*`).

## Why
Vue 3.5's reactivity is a precise algorithm (version-counted doubly linked `Link`s between `Dep`s and subscribers, `batch()`, lazy `computed` with `globalVersion`, scope ownership). Observable behaviour (how many times a getter ran, in which order effects/watchers fire) is the compatibility contract (R04, R05). You **port the behaviour** of this part of `@vue/reactivity` 3.5.43 to Rust over the `vn-value` runtime. Write your own implementation; do not translate line by line without understanding (licensing: keep a one-line `// behaviour per @vue/reactivity 3.5.43` attribution).

## Scope (this WP)
Everything in the reactivity package except the Proxy-based `reactive/readonly/shallow*` wrappers, array/collection instrumentations and the `toRaw/markRaw/isReactive…` family (that is WP-R1b, which builds on your `track/trigger` and ReactiveFlags):
- Subscriber/Dep/Link graph exactly as 3.5 (flags `ACTIVE RUNNING TRACKING NOTIFIED DIRTY ALLOW_RECURSE PAUSED EVALUATED`), `activeSub`, `shouldTrack`, `pauseTracking/enableTracking/resetTracking`, `globalVersion`, `startBatch/endBatch` (the ordering of batched subscriber notification — including the "notify in reverse and run in original subscription order" effect — must match), `Dep.track/trigger/notify`, `targetMap` keyed by (target object, key) **stored in the target object's `ext` slot** (so no weak tables are needed), `ITERATE_KEY/ARRAY_ITERATE_KEY/MAP_KEY_ITERATE_KEY` constants, `track(target,type,key)` and `trigger(target,type,key,newValue,oldValue,oldTarget)` with the array-length/ITERATE special cases (implement the generic algorithm; R1b supplies instrumentation).
- `ReactiveEffect` (internal) + `effect()`/`stop()` + `onEffectCleanup` + `pause/resume` (these are *not* exported to user code per the manifest, but `watch` is built on them and tests need them: expose them as Rust API and as hidden helpers under a `__internal` namespace of the module exports table the tests can use).
- `EffectScope`: `effectScope(detached)`, `getCurrentScope`, `onScopeDispose(fn, failSilently)`, `scope.run/stop/pause/resume/on/off/active`, nesting, detached scopes, stop propagation and cleanup ordering.
- `ref`, `shallowRef`, `triggerRef`, `customRef`, `toRef` (property/getter/value forms), `toRefs`, `toValue`, `unref`, `isRef`, `proxyRefs` (internal), `Ref` identity flags (`__v_isRef`), deep wrapping of ref values via a hook that R1b fills in (`toReactive(value)` stays identity until R1b registers `reactive`; design it as a replaceable function pointer in the reactivity state).
- `computed(getter | {get,set}[, debugOptions])`: lazy, cached, `refreshComputed`, branching dependencies, `oldValue` argument, writable computed, `isReadonly/isRef` flags, error propagation, self-referencing cycles as 3.5.
- The reactivity-level `watch(source, cb, options)` base of 3.5 (`@vue/reactivity`'s `watch`, `WatchHandle`, `onWatcherCleanup`, `getCurrentWatcher` internals, options `immediate/deep/once/scheduler/augmentJob/call/onWarn`) — the runtime's `watch/watchEffect*` wrappers (scheduler integration) are WP-RT1; expose what RT1 needs as Rust API (`watch_base(rt, source, cb, WatchOptions) -> WatchHandle`) and document it.
- JS surface: `pub fn exports(rt: &Rt) -> Vec<(&'static str, Value)>` returning the `vue` module exports this crate owns that the manifest marks P/A for user code (`ref shallowRef triggerRef customRef toRef toRefs toValue unref isRef computed effectScope getCurrentScope onScopeDispose` and the internal-flag helpers marked `compilerInternal`), as native function objects with correct `name`/`length`; plus a Rust API for the same. Registering the `vue` module itself is done by a later aggregator; for tests register your own native module `"vue"` via `rt.register_native_module`.
- Representation: refs/computed/scopes are heap objects (`Exotic` with `get/set` hooks for `value`, `__v_isRef`, `__v_isReadonly`, `__v_isShallow`, `effect`, `dep`…, or `Native` + native methods — your choice, documented) so they can be passed around as JS values and traced by the GC; all Rust-side graph state implements `NativeObject::trace` and is reachable from a root (`rt.add_root_provider` or the global `registry`). Dispose semantics: stopping a scope/effect releases its links so unreachable graphs are collectable (test with `collect()` + live-object counts).

## Tests
- `crates/reactivity/tests/*.rs` (Rust): ≥ 80 behavioural tests written against the *behaviour of the real package*: for each, a comment cites the equivalent Vue snippet and the expected trace was **obtained by running that snippet in Node with vue@3.5.43** (write a tiny generator script `tests/vue/rust/gen-expected.mjs` that runs snippets from a JSON list and writes `tests/vue/rust/expected.json`; the Rust tests include it with `include_str!` and look results up by id). Use native closures (`new_native_function` with `data`) as effect/getter/callback bodies, with a shared log array.
- Cover: effect run counts and cleanup, conditional dependencies, nested effects, batch ordering with multiple effects/computeds on one dep, computed laziness/caching/diamond/chain, unchanged-result suppression, writable computed, `oldValue`, scope stop order, `onScopeDispose`, detached scopes, ref identity/`Object.is`, `shallowRef`+`triggerRef`, `customRef`, `toRef/toRefs` aliasing, `toValue/unref/isRef`, `watch` base options (immediate/once/deep/ cleanup/pause/resume/stop), error in getter/callback, self-triggering effects (`ALLOW_RECURSE`), GC safety (collect between steps; no leaks after stop).
- **Final acceptance target (after the compiler exists):** the 102 scenarios in `tests/vue/cases` run through `tooling/harness` with a `vue` native module built from this crate must match their goldens for the groups `ref`, `computed`, `effect` and the scenarios of `watch`/`scheduler` that do not need `nextTick`/microtask ordering (the scheduler is WP-RT1). Prepare the glue: `crates/reactivity/src/testing.rs` with `pub fn register_vue_for_tests(rt: &Rt)` and document how the harness should call it; the coordinator will wire it.
- Mutation check: in a scratch copy, break the batch ordering and the computed cache; show the tests fail.
