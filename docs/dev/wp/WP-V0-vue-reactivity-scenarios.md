# WP-V0 — Vue reactivity & scheduler scenario corpus with goldens from the real `vue@3.5.43`

Read `docs/dev/AGENT-CONTRACT.md`, `docs/dev/trace-format.md`, `docs/dev/ARCHITECTURE.md`. WP id `v0` (no cargo).
**Prerequisite:** WP-O1 done (`tooling/oracle/*`, scenario contract, 60+ language cases). Read `tests/language/cases/README.md`.
**Owned paths:** `tests/vue/cases/**`, `tests/vue/golden/**`, `tests/vue/oracle.test.mjs`, `tooling/oracle/vue-env.mjs`
(the only oracle file you may add; do not edit O1's files — if you need a change, request it).

## Why
Reactivity (V01–V17) and scheduling must match Vue **exactly**: same effect-run counts, same ordering of watcher
callbacks relative to promise jobs, same identity rules. The real package is the oracle. We will later compile these same
scenario files to Rust and compare traces, so scenarios must be valid in our profile (see the forbidden list in WP-O1)
**and** must not observe Vue internals that our port cannot reproduce.

## Do
1. `tooling/oracle/vue-env.mjs`: the way Node scenarios load Vue. Scenarios `import { ref, … } from 'vue'`. Decide and
   document whether the oracle uses the production build (`vue.cjs.prod.js`, NODE_ENV=production — **required default**: dev-only
   warnings and checks are not part of the contract) — set `NODE_ENV=production` for the child process. If O1's runner
   cannot be parameterised by environment, add a thin wrapper `tooling/oracle/run-vue.mjs` in your owned path that sets the
   env and delegates (do not copy its logic).
2. 90–120 scenarios under `tests/vue/cases/<group>/<name>.js` (same header tags as language cases: `// @tier N`,
   `// @covers V01,V06`), goldens in `tests/vue/golden/` generated by Vue (prod build) via the oracle runner:
   - **ref** (V01,V02,V07,V08,V10,V11): get/set, `Object.is` semantics (NaN, -0), deep wrapping of plain objects/arrays,
     `shallowRef` + `triggerRef`, `isRef/unref/toRef/toRefs/toValue` incl. getter form and object property aliasing,
     `customRef` with track/trigger, `markRaw`/`toRaw`, refs inside reactive objects (auto-unwrapping, not for arrays/Map
     elements), `ref` of a reactive proxy identity.
   - **reactive** (V03,V04,V05,V09,V10): get/set/has/delete/`Object.keys`/`for in`/spread tracking, array index/length/
     `push/pop/shift/unshift/splice/sort/reverse`, identity-sensitive array search (`includes/indexOf/lastIndexOf` with raw
     and proxied elements), `Map`/`Set` (get/set/add/delete/has/clear/size/forEach/entries/keys/values/iteration while
     mutating), nested proxy caching (`reactive(o) === reactive(o)`, `reactive(reactive(o)) === reactive(o)`,
     `readonly(reactive(o))`), `shallowReactive`, `shallowReadonly`, `readonly` write rejection (silent in prod — assert the
     value is unchanged), `isReactive/isReadonly/isProxy/isShallow`, non-extensible/frozen/`markRaw` targets,
     symbol keys, getters on reactive objects with `this`/receiver, effects tracking via `has` and via iteration.
   - **computed** (V06): laziness (count getter calls), caching, invalidation through chains and diamonds, branch switching
     (conditional deps), unchanged result does not re-trigger dependents, writable computed, `oldValue` argument (3.4+),
     computed in watchers/effects, errors thrown in getter and recovery, computed reading itself (cycle behaviour).
   - **effect & scopes** (V12, advanced): `effect()` run counts, `scheduler`, `stop`, `onStop`, nested effects, `effect.pause/
     resume`, recursion, `effectScope()` nesting/detached/`stop`, `onScopeDispose`, `getCurrentScope`, cleanup order.
   - **watch** (V13–V16): all source forms (ref, getter, reactive object, array of sources), `immediate`, `once`, `deep` incl.
     numeric depth, `flush: 'pre'|'post'|'sync'` ordering relative to each other, to `nextTick`, to `Promise.resolve().then`
     and to plain microtasks, callback `onCleanup` and `onWatcherCleanup`, handle `stop/pause/resume`, writes while paused,
     watch stop inside callback, multiple writes coalescing, old/new values, `watchEffect/watchPostEffect/watchSyncEffect`
     including dependencies registered only before the first `await`, watcher triggering another watcher.
   - **scheduler/nextTick** (V17): `nextTick()` with and without callbacks, returned promise ordering vs other jobs, writes
     inside nextTick, jobs added during a flush, recursive updates (guard against runaway: the scenario must terminate).
   Trace **only plain snapshots**: never pass a reactive proxy to `trace` (tracing reads it → subscribes). Provide a local
   helper inside each scenario that snapshots via `toRaw` + manual copy where needed. Track run counts with plain counters.
   Do not use component APIs or the DOM here (another WP covers components). No `console`, no timers except
   `testHost.timers`.
3. `tests/vue/oracle.test.mjs` (node:test): goldens match a fresh oracle run for every scenario; run each twice for
   determinism; a lint (reuse `tooling/oracle/lint-cases.mjs` if it can be pointed at another directory, else a small copy-free
   wrapper) proves no forbidden construct is used; **negative control**: a scenario with a deliberately wrong golden fails;
   a scenario list audit: every V01–V17 row of `compiler/profile/inventory.generated.json` is covered by ≥ 2 scenarios.
4. `tests/vue/README.md`: how the corpus is organised, how to add a scenario, the "never trace a proxy" rule, known Vue
   behaviours that look surprising and are asserted on purpose.

## Acceptance
`node --test "tests/vue/oracle.test.mjs"` passes; goldens regenerate byte-identically (`node tooling/oracle/check-goldens.mjs`
equivalent for tests/vue, written inside your owned path); every scenario file has the header tags and is accepted by the lint.
